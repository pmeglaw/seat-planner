# Phase 4 · PR 1 captures — tokens and CSS landing (2026-09-03)

**What these show.** The shipped components sitting on the Phase 3 token layer, before any component is
rebuilt — the state the hand-off calls "looks wrong by design": Carbon greys and Blue 60 on today's layouts,
the orange and the shadows gone, dark theme = Carbon g100. They exist so the PR 1 preview walk has a
reference and so PR 2–5 can show what each surface looked like before its rebuild.

**Source.** Branch `feat/phase4-tokens` (PR 1), `npm run dev` against the **local Docker Supabase stack**
(`npm run db:start` + `db:seed`; `.env.local` pointed at `http://127.0.0.1:54321` for the run and restored
after). Signed in as the seeded local admin `e2e-admin@example.test`. **No production data and no
production write**: every name, seat and count on these pages is `supabase/seed.sql` sample data.

**Method.** Playwright `chromium.launch({ channel: "chrome" })`, viewport 1920×1080, device scale 1, after
`document.fonts.ready` + 800 ms; theme set by writing `sp-theme` to localStorage and reloading, so the boot
script derives `data-theme` / `data-carbon-theme` exactly as a user's browser would. The same run performs
the undefined-`var()` audit (every `var(--…)` in a rule that matches an element on the page must resolve on
`:root` or on some element) and captures the 1024×768 narrow frame for each route in the light theme.
