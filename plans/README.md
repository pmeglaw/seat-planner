## Considered, not planned this cycle

Real findings, verified at HEAD, deliberately **not** turned into plans now (the user scoped this cycle to the confirmed correctness/security defect backlog). Recorded so they are not re-audited from zero; each is a candidate for a future `improve` cycle.

**Structural (high value, larger effort):**
- **SeatMap.tsx god component** — grew to 3,883 lines / 127 hooks / 5 inline dialogs (was 2,684 at prior audit). Incremental decomposition (dialogs → components, then `usePublishReview` / `useDraftHistory` / `useSeatFilters` hooks). The concurrency contract lives here; extract state *with* its re-sync effects.
- **12 hand-rolled modal dialogs, no shared primitive** — an `Overlay` + `ConfirmDialog` extraction would make dialog a11y structural instead of per-instance (and would give plan 002's error region + Escape wiring a permanent home). `components/ui/useDialogFocus.ts` already shares the focus half.
- **164 raw hex literals bypass `--sp-color-*` tokens across 14 files** (was 67/6); two competing marker-color sources of truth (`SeatMarker.tsx` ships; `design-system.tsx markerStateClassRecipes` is prototype-only). Deleting the prototype recipe removes 48 in one commit.
- **`seat.zone ?? seat.department` open-coded at ~20 sites** with 5 divergent empty-value conventions — a `getSeatZone(seat, { fallback })` extraction; the R-13 taxonomy migration will need this first.
- **Viewer/admin render duplication** — office-wash JSX + `MAP_ZOOM_*` constants copy-pasted (logic is properly shared via `lib/officeRoomWash.ts`); `ResultsPanel` shared on admin, hand-rolled twin on viewer coupled by `aria-label` string.

**Test infrastructure (the verification gate for future work):**
- **TEST-01 → now Plan 007** — the PGlite tier runs as the table owner, so RLS policies and the seat-protection delete trigger are never actually executed. Plan 007 adds a `set role authenticated` + table-grants path and asserts viewer-cannot-read-draft / cannot-write-`published_employees` / original-delete-refused. **This is the verification any future RLS change needs** (and Plan 008 uses it). (Note: the earlier `force row level security` sketch is *wrong* — the policies are `to authenticated`, so forcing RLS as the owner default-denies everything; Plan 007's STOP conditions call this out.)
- **TEST-02 → now Plan 009** — `restore_draft_snapshot` and 3 management RPCs (`delete_department`, `rename_zone`, `delete_zone`) are still string-tested only; Plan 009 adds PGlite execution tests (the reset block + `rename_department` test are the templates).
- **TEST-03** — the c8 gate uses `"all": false`, so 6 never-imported `lib` files (incl. `adminPageGuard.ts`, `supabase/authRedirect.ts` — both security-adjacent) are invisible to the coverage floor. Flip to `all: true` with an explicit exclude list.
- **TEST-05** — calibration behavior test covers 1 area / 1 axis; add zero-fixture round-trip identity per area + overlapping-area selection assertions.
- **TEST-07** — `repair_original_is_custom` regex duplicates `lib/seatProtection.ts` prefix ranges, unpinned and already divergent on unpadded labels (`N7`).
- **Browser-harness gap (surfaced executing plan 002) → now Plan 010** — `tests/browser/build-harness.ts` stubs `auth.signOut` but not `auth.getUser`, so any browser spec combining `canEdit:true` with a rejected action crashes on SeatMap's session-expiry probe effect (`getUser()` on the mock). Plan 010 adds the `getUser` stub (unblocking the whole class of admin-mutation error-path browser tests) and lands 002's missing discard-error regression test. Connects to TEST-04.
- **Browser-harness `pending` never settles (found executing Plan 010)** — in the CSS-less SeatMap browser harness, the ResizeObserver layout-measurement effects never converge, so the component re-renders continuously and React's `useTransition` `pending` flag stays stuck `true`. Consequence: browser specs can observe that a mutation's error/success *message* appeared, but NOT any UI gated on the transition *settling* (e.g. a button relabeling from "Discarding…" to "Retry discard"). Plan 010's 002 spec asserts the in-dialog alert (which works) and documents the omitted relabel. Fix options for a future plan: gate the affected buttons on `mutationInFlight` the way Undo/Redo already do (a SeatMap change), or give the harness minimal real layout/CSS so measurement converges (a harness change). Scope it to `SeatMap.tsx` and/or `tests/browser/harness.ts`.
